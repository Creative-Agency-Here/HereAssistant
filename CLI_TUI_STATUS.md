# HereAssistant CLI TUI — текущий статус

> Обновлено: 2026-07-24. Статус сверён с текущим кодом и регрессионными тестами.

## Стек и источники истины

- Ink 5 + React 18 + TypeScript.
- `cli/src/mouse-filter.ts` нормализует терминальные escape-последовательности.
- `cli/src/components/ChatInput.tsx` управляет многострочным буфером и курсором.
- `cli/src/ha-sessions.ts` хранит HA-сессии в `~/.hereassistant/sessions/`.
- `cli/src/components/SessionPicker.tsx` показывает список и превью `/resume`.
- Автотесты ввода: `cli/src/mouse-filter.test.ts` и
  `cli/src/components/ChatInput.test.tsx`.

## Исправленные причины багов

### Стрелки

В CSI-последовательности `\x1b[D` направление находится в terminator (`D`), а
`inner` пуст. Старый код искал `D` в `inner`, поэтому событие не создавалось.
Теперь CSI, SS3 и Kitty navigation keys нормализуются в один тип события.

### Курсор и paste

`cursorLine`/`cursorCol` и их refs раньше обновлялись разными вызовами, из-за чего
React batching возвращал устаревшую позицию после paste, удаления строки и быстрого
ввода. Теперь все критические операции синхронно обновляют state и refs через один
путь.

После удаления пустой второй строки Ink мог не дорисовать `▌` в первой строке,
несмотря на правильные state/refs. Поддерево строк теперь получает key от длины
буфера и позиции курсора, поэтому структурное удаление гарантированно создаёт новый
визуальный кадр. Регрессионный тест проверяет именно кадр `текст▌`, а не только
последующую отправку текста.

### Mouse, click-to-cursor и selection

Два старых mouse-handler одновременно считали input по разным формулам от нижнего
края терминала. Теперь используется один handler: на mouse-down он читает фактические
координаты Yoga-layout у Ink-узла ввода и сразу переносит курсор в выбранную строку
и колонку. Mouse move отделён от press/release, поэтому drag больше не сбрасывает
начало выделения на каждом событии.

Локальный Claude Code 2.1.207 использует собственный renderer-selection:
`copyOnSelect` включён по умолчанию, а на mouse release вызывается
`copySelectionNoClear()`. В HA автокопирование намеренно выключено: одиночный click
остаётся позиционированием курсора, drag рисует inverse-selection, release сохраняет
его, а `Cmd+C` явно копирует текст. Поле ввода отделено от selection чата через
hit-test, поэтому два обработчика больше не перехватывают один жест одновременно.
Реальный stdin переводится в raw mode до запуска Ink, а `exitOnCtrlC` отключён:
`Ctrl+C` обрабатывается приложением и завершает HA. `Cmd+C` приходит через Kitty
CSI u; расширение VS Code отправляет ту же последовательность отдельной командой,
чтобы встроенный terminal copy не поглотил shortcut.

Старая карта строк чата использовала искусственные номера от нуля и сравнивала их с
абсолютными terminal row, из-за чего визуальное выделение и скопированный диапазон
расходились. Теперь строки welcome-экрана, чата и tool output регистрируют абсолютные
координаты фактического Ink/Yoga layout; тот же hit-map обслуживает клики по
tool-блокам.

### Двойной Enter

Старый вариант отправлял запрос на первом Enter, поэтому второй уже не мог создать
перенос. Теперь одинарный submit ждёт 50 мс; второй Enter в этом окне отменяет его и
вставляет newline.

### Bracketed paste

Marker `201~` мог выключить флаг paste до того, как Ink обработает накопленный chunk.
MouseFilterStream теперь преобразует CR/LF в Ctrl+J непосредственно во время разбора
paste, сохраняя порядок текста и переносов.

### `/resume`

Восстановлен отдельный resume-mode: загрузка через команду, пикер или `--resume`
помечает диалог как продолженный. ESC до первого нового сообщения очищает загруженную
историю и возвращает к новой HA-сессии.

### Безопасный ESC и очередь запросов

Поле ввода остаётся активным, пока агент работает. Enter сохраняет текст и вложения
в FIFO-очередь, очищает поле и автоматически запускает следующий запрос после
завершения или отмены текущего.

ESC с непустым черновиком очищает только черновик. При пустом поле и занятом агенте
первое нажатие показывает `Esc ещё раз — отменить текущую работу` и включает окно
подтверждения на 1,5 секунды; только второе нажатие в этом окне отправляет сигнал
текущему provider-процессу. Shift+ESC всегда остаётся безопасным no-op: текст и
работа не меняются.

### Privacy и clipboard

Лог клавиш в `/tmp/ha-keys.log` выключен по умолчанию и доступен только при явном
`HA_TUI_DEBUG_KEYS=1`. Копирование текста вызывает `pbcopy` без shell-интерполяции
пользовательского содержимого. В PTY smoke-test clipboard перед проверкой сохранялся
и после неё восстанавливался без вывода его содержимого.

## Осознанные trade-offs

| Фича | Статус | Причина |
|---|---|---|
| Обычный drag как нативное выделение | ⚠️ | Drag принадлежит HA; для terminal-native selection нужен Shift+drag |
| Собственное выделение HA | ✅ | Input и chat проверены в живом PTY; `Cmd+C` копирует выбранный диапазон |
| Клик по tool-блоку | ✅ | Tool header регистрируется в общем screen-row hit-map |
| Copy mode (F9) | ❌ | Не реализован, Gemini-only сценарий |
| Vim mode | ❌ | Не запрашивался |
| OSC 52 clipboard | ❌ | На macOS используется `pbcopy` |

## Финальный code review

Code review: пройдено.

Отдельная проверка всего diff выявила и закрыла четыре дефекта:

- custom ESC теперь доходит до списка и превью `/resume`;
- provider timeout очищается после завершения и принудительно останавливает процесс
  при срабатывании, поэтому Node не удерживается пять минут;
- намеренная отмена отображается как `⏹ текущая работа отменена`, active process
  очищается после close/error, а `Ctrl+C` завершает дочерний процесс;
- HA session ID валидируется против path traversal, JSON проверяется перед загрузкой,
  а приватные session-файлы записываются атомарно с правами `0600` в каталоге `0700`.

Дополнительно добавлен корректный non-TTY `ha --help`. После исправлений повторно
пройдены typecheck, 20/20 CLI-тестов и живые PTY-сценарии `/resume → ESC`,
двойная защищённая отмена и однократный `Ctrl+C`.

## Интерактивный smoke-check перед релизом

Автотесты закрывают детерминированную логику, но перед публикацией CLI всё равно
нужно один раз проверить в целевых терминалах:

1. `ha -a local-codex` в VS Code terminal.
2. `ha -a local-qwen` в Ghostty или Terminal.app.
3. Стрелки, Home/End, Ctrl+←/→, Shift/Option+Enter.
4. Одно- и многострочный paste, фото через Ctrl+V.
5. `/resume` → выбор → Enter → ESC.
6. Во время работы ввести второй запрос → Enter → увидеть очередь; первый ESC
   показывает защиту, второй отменяет текущую работу, очередь запускается.
7. Ввести черновик → Shift+ESC не меняет его → обычный ESC очищает.
8. Backspace на пустой второй строке → `▌` в конце первой.
9. Клик между символами → следующий символ вставляется в выбранную позицию.
10. Drag-выделение HA → `Cmd+C`; отдельно Shift+drag для нативного выделения
   терминала.
